# מיפוי שוק הכרמל

טופס מובייל לפעילים שעוברים בין הדוכנים, ומפה עם ייצוא לאקסל.
האתר הוא קבצים סטטיים (HTML/JS, בלי build). הנתונים נשמרים ב-**Google Sheets**, והתמונות בתיקייה ב-**Google Drive**, דרך סקריפט קטן של Google Apps Script שרץ על החשבון שלך.

```
index.html            הטופס (דיווח / להשלים / צומת)
map.html              מפה, סינון, ייצוא Excel ו-JSON
config.js             כתובת השרת (API_URL)
assets/               JS ו-CSS
data/addresses.json   כתובות רובע 5 (5,863 כתובות, 58 מהן ברחוב הכרמל)
data/junctions.json   צמתים לאורך הכרמל, מחושבים מראש
apps_script/Code.gs   צד השרת (מדביקים ל-Apps Script)
scripts/build_data.py בונה מחדש את data/ מתוך הריפו kalpi-map
```

## מצב הדגמה

כש-`config.js` מכיל `API_URL: 'mock'` (ברירת המחדל), כל קוד נכנס והנתונים נשמרים רק בדפדפן. כך אפשר לנסות את הכול לפני שמחברים את גוגל:

```bash
python3 -m http.server 8000
```

ואז לפתוח את http://localhost:8000.

## התקנה (פעם אחת, כ-10 דקות)

1. **גיליון:** פותחים Google Sheet חדש, למשל בשם "מיפוי שוק הכרמל".
2. **סקריפט:** בגיליון בוחרים **Extensions → Apps Script**, מוחקים את מה שיש ומדביקים את כל התוכן של `apps_script/Code.gs`. שומרים.
3. **setup:** בעורך בוחרים את הפונקציה `setup` ולוחצים **Run**. גוגל יבקש הרשאות לגיליון ולדרייב, מאשרים.
   הסקריפט ייצור את הלשוניות `users`, `businesses` ו-`junctions`, ואת התיקייה "שוק הכרמל - תמונות" בדרייב שלך. בלשונית `users` תופיע שורה ראשונה עם קוד בשבילך.
4. **פריסה:** **Deploy → New deployment**, ובסוג בוחרים **Web app**:
   - *Execute as*: **Me**
   - *Who has access*: **Anyone**. זה לא חושף את הנתונים: כל בקשה חייבת קוד פעיל מהלשונית `users`.
   מעתיקים את ה-URL שמסתיים ב-`/exec`.
5. **חיבור:** ב-`config.js` מחליפים את `'mock'` ב-URL שהעתקת.
6. **העלאה:** מעלים לדומיין את כל הקבצים: `index.html`, `map.html`, `config.js`, `assets/` ו-`data/`. אין צורך ב-`apps_script/` ו-`scripts/`.

### ניהול פעילים
בלשונית `users`, שורה לכל פעיל: **שם | קוד | פעיל** (TRUE/FALSE).
- מוסיפים פעיל עם קוד ארוך ולא צפוי, למשל 8 תווים אקראיים.
- כדי לחסום פעיל משנים את "פעיל" ל-FALSE. זה תופס מהבקשה הבאה שלו.
- השם שבעמודה הראשונה נרשם אוטומטית בעמודה "מילא/ה" של כל דיווח שהפעיל שולח.

### עדכון קוד השרת
אחרי שינוי ב-`Code.gs`: **Deploy → Manage deployments → ✏️ → Version: New version**. כך ה-URL נשאר אותו URL.

## איך זה עובד בשטח

- **דיווח:** בוחרים רחוב ומספר, ומיד מוצג הצד (זוגי/אי-זוגי). ה-GPS נשמר ברגע בחירת הכתובת ושוב בשמירה.
  לכל עסק בכתובת מוסיפים כרטיס ("+ עסק נוסף") עם סוג מבנה (בסטה/חנות) והפרטים.
  לעסק סגור מסמנים **"סגור – יושלם בהמשך"**. אחרי השמירה הטופס עובר לכתובת הבאה באותו צד.
- **להשלים:** רשימה של כל העסקים שסומנו סגורים. פעיל אחר לוחץ "השלמה" וממלא.
- **צומת:** צמתים שחושבו מראש (שפ"ר, רמב"ם, קלישר, יעבץ ועוד). כשמגיעים לצומת לוחצים "אישור". צומת שחסר ברשימה מוסיפים ידנית.
- **בלי קליטה:** הדיווח נשמר בטלפון, וליד שם הפעיל מופיע מונה "ממתינים לשליחה". השליחה נעשית אוטומטית כשהרשת חוזרת. שליחה כפולה לא יוצרת שורה כפולה.
- **מפה:** נקודה אפורה = לא נסקר, ירוקה = מולא, כתומה = יש מה להשלים. יש סינון לפי סוג עסק, "מקושר ל-" וסוג מבנה, וייצוא לאקסל (לשוניות עסקים וצמתים) או ל-JSON.
  הגיליון עצמו בגוגל הוא גם קובץ האקסל: File → Download → xlsx.

## הערות

- **פרטיות:** המאגר מכיל שמות, טלפונים ותמונות. כל פעיל עם קוד יכול לראות את כל הנתונים במפה (צריך את זה בשביל רשימת "להשלים"). הגיליון והתיקייה בדרייב נשארים פרטיים שלך.
- **הצמתים המחושבים הם הערכה.** הם חושבו מקווי הרחובות של OSM ומהקואורדינטות של הכתובות. יש רחובות, כמו השומר, שלא הופיעו בנתונים, ולכן מוסיפים אותם ידנית בשטח.
- **הרחבת האזור:** `python3 scripts/build_data.py /path/to/kalpi-map`. תתי-הרובעים מוגדרים ב-`ROVA_ZONES`.
